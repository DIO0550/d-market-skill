# Quiz

学習クイズの**生成・出題・進捗管理**を行うスキル。進捗はスクリプト経由でファイルに永続化され、セッションをまたいで「未出題→苦手→習熟済み」の優先度で復習を回せる。

**鉄則（進捗が消える事故を防ぐため厳守）：**

1. 進捗データ（questions.json / progress.json）を**直接読み書きしない**。必ず `scripts/` を経由する
2. 回答を採点したら**その場で毎回** `record-answer.sh` を実行する。セッション末尾でのまとめ記録は禁止（中断で消える）
3. 進捗の数値（正答率・習熟数など）は `show-progress.sh` の出力を**そのまま**使う。モデルが暗算・再集計しない

スクリプトの一覧とデータスキーマは [references/schemas.md](references/schemas.md) を参照。

---

## モード判定

ユーザーの依頼から3つのモードのいずれかに入る。いずれも最初に `scripts/init-workspace.sh` を実行してワークスペースの現状（バンクの問題数・トピック）を確認する。

| 依頼 | モード |
|---|---|
| 「クイズを出して」「復習したい」 | 出題（問題が足りなければ先に生成） |
| 「〜の問題を作って」「問題を増やして」 | 生成のみ |
| 「進捗を見せて」「どれくらい覚えた？」 | 進捗確認のみ（`show-progress.sh` を実行して提示） |

確認すべきことが1つだけある：**トピック**。依頼から明らかならそれを使い、不明なら init-workspace.sh が表示した既存トピックを提示して選んでもらう。バンクが空なら何のクイズを作るか（一般知識か、リポジトリの資料ベースか）を確認する。

## Phase 1: 問題生成（サブエージェント委譲）

対象トピックの問題が不足しているとき（目安：未出題＋苦手が出題数に満たない、またはユーザーが生成を依頼したとき）に実行する。

**生成はサブエージェントに委譲する。** メインスレッドで問題を作るとコンテキストを消費し品質も安定しないため、[agents/question-generator.md](agents/question-generator.md) を読み、その指示をプロンプトにしてサブエージェントを起動する。

- **1トピック=1エージェント**とし、複数トピックは**同じターンで並列起動**する
- 各エージェントに渡すもの（詳細は agents/question-generator.md の冒頭）：
  - トピック名・生成数（既定10問）・難易度配分（easy 3 / medium 4 / hard 3）
  - 調査対象（リポジトリ資料のパス、または「一般知識で可」）
  - **同トピックの既存問題文リスト**（`pick-questions.sh 9999 <トピック>` の出力から question を抜粋。重複生成の防止）
  - 出力先: `<workspace>/incoming/<トピックslug>-<連番>.json`
- エージェント完了後、出力ファイルごとに `scripts/add-questions.sh <ファイル>` でバンクにマージする
- マージ結果（added / skipped / invalid）を確認し、**invalid が出た場合はその理由を確認して該当エージェントに再生成させる**（invalidの問題は捨てられている）
- added の合計が目標数の半分未満なら、不足分を追加生成する

サブエージェントが使えない環境では、agents/question-generator.md の品質基準を自分で読み、同じ基準で生成して同じフローでマージする。

## Phase 2: 出題

1. `scripts/pick-questions.sh <出題数> [トピック]` で出題対象を取得する（既定5問。ユーザー指定があればそれに従う）
2. **1問ずつ**出題する。複数問を一度に見せない
   - multiple_choice: 選択肢を提示する。選択式の質問ツール（AskUserQuestion等）が使えるなら選択肢をそのまま options にする（4択がちょうど収まる）
   - free_text: 問題文のみ提示し、自由回答してもらう
   - **回答前に answer / explanation を絶対に見せない**
3. 採点する
   - multiple_choice: answer と一致すれば correct
   - free_text: answer（模範解答の要点）と照らして判定。要点を満たしていれば表現が違っても correct。判定に迷う場合はユーザーに模範解答を見せて自己判定してもらう
4. **即座に** `scripts/record-answer.sh <question_id> <correct|incorrect>` を実行する（次の問題に進む前に必ず）
5. 正誤と explanation（誤答時は特に丁寧に）を伝えてから次の問題へ
6. ユーザーが「やめる」と言ったらそこで打ち切ってよい（記録済みの分は保存されている）

---

## Phase 3: セッションサマリ

出題が終わったら `scripts/show-progress.sh [トピック]` を実行し、その出力を基に提示する：

- 今回の結果（何問中何問正解か）
- 全体進捗（着手率・正答率・習熟済み数）— スクリプト出力の数値をそのまま使う
- 苦手問題があれば「次回はここを復習する」ことを提案
- 未出題が残り少なければ問題の追加生成を提案

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| `pick-questions.sh` が「問題がありません」 | Phase 1 で生成してから出題する |
| `record-answer.sh` が「IDが存在しません」 | pick-questions.sh の出力に含まれる `id` をそのまま使う（自分でIDを組み立てない） |
| `add-questions.sh` で invalid 多発 | エージェント出力がスキーマ（answerとchoicesの完全一致など）に沿っているか確認し再生成 |
| progress.json が壊れた | history.jsonl から再構築できる。ユーザーに報告してから復旧する |
